# 共有グループの編集・競合監査（2026-10-27）

## 範囲

共有開発ブランチの `7dc8210` を基点に、個人用DBと共有用DBの分離、保存する項目の差分、SQLiteとOutboxの同時保存、競合の解決、権限が変わる瞬間、グループの日付、画面更新を照合した。既存の機能契約79件を維持し、問題が見つかった経路へ回帰検査を追加した。

## 修正

| 問題 | 修正と検査 |
| --- | --- |
| 古いゴミ収集日の編集画面から保存すると、別端末の新しい周期や名前を戻せる | 編集開始時の値を保存処理へ渡す。名前と収集ルールのうち実際に編集した側だけを適用し、同じ側を別端末も変更していた場合は保存を拒否する。編集していない旧画面の保存では変更イベントを作らない。削除済みの登録も復活させない。共有DBの3ケースは修正前の失敗と修正後の成功を確認した |
| 曜日と隔週設定を別々の端末で変えると、双方の一部が混ざって無効な収集ルールになる | 周期・曜日・基準日・毎月の日付を1組として変更イベントへ保存する。オフラインの競合を検出し、候補の採用時もその組をまとめて適用する。通常の名前などの項目別解決、削除・復元、旧形式の操作は維持する |
| 競合解決がDBの書き込み待ちになった後、アカウントが切り替わっても処理を進められる | トランザクション内と派生データ保存の前後でも許可を照合する。途中の失敗では変更・Outbox・派生行を一緒に戻す既存の境界を使う |
| ゴミの登録初期値が端末の日付に依存する | 共有Snapshotの日付を編集画面へ渡す。毎月の日付と隔週の基準日をグループの共通日付から決める。個人の初期設定画面での従来の動作も維持する |
| 競合で予定が止まっても、通常画面に理由が出ない | ホーム・カレンダーなど共通のページに確認案内を表示し、共有の管理画面へ移動できるようにする。既存のPlanner購読から件数だけを読むため、新しいDB読み込みや同期処理は増やさない。解決後、個人モード、別グループへの切り替え後には残さない |

収集ルールを1組で扱うのは、それぞれの入力値が互いを制約するためである。単に曜日を後勝ちで合成すると、基準日と曜日が一致しない隔週設定を作れてしまう。独立した名前の変更まで収集ルールの競合に巻き込まない。

## 物理端末

iPhone 12 / iOS26.7.1はXCTest、Sony I4293 / Android10はADBを使い、開発ビルドと実Googleアカウント・本番Firestoreで次を検査した。端末の初期化・アンインストール・個人データの共有への取り込みは行っていない。

| 実際の操作 | 結果 |
| --- | --- |
| iPhoneに毎週火曜の編集画面を残し、Androidで隔週木曜へ変更。その後iPhoneから名前だけを変更 | 名前を保存でき、Androidが変更した隔週木曜を保持。両端末の状態一致 |
| iPhoneの編集開始後、Androidから同じ名前を変更。iPhoneから別名で保存 | iPhoneで最新の内容を開き直す案内を表示。変更イベント・未送信操作を追加せず、両端末の状態一致 |
| Androidを通信断にして毎週木曜を保存。同じ旧状態からiPhoneで隔週火曜を保存 | Androidは未送信1件を端末内に保持。通信復旧後のアプリ再起動でも失わず再送し、両端末で競合を検出 |
| 通常ページの確認案内を押す | 両実機で表示と管理画面への移動を確認 |
| 基準日10月27日の候補をAndroidで採用 | 周期・曜日・基準日をまとめて採用し、両端末で「隔週火曜・基準日10月27日」へ一致 |
| 検査用の収集ルールを削除 | 両端末の共有業務状態が検査開始前と一致。検査の変更イベント・削除記録は通常の同期履歴として保持 |
| 修正後に共有→個人→共有を各端末で2往復 | 個人モードに共有の確認案内が残らず、共有ホームへ戻れる。解決済みの案内も消える |

最終状態は両端末とも受信位置71、未送信0件、同期エラーなし、SQLiteの整合性ok。共有業務状態のハッシュは両端末で一致し、検査開始前とも一致した。個人DBは、家事・設定・履歴・家電・ゴミ・Google Taskの対応を含む12テーブルの全行が、それぞれの端末の検査前と完全に一致した。古いバックアップを端末へ書き戻す操作はしていない。

Wi-Fiは保存済みの接続先の「接続」で復旧でき、パスワードの参照・入力は行っていない。ネットワークをOFFのまま残していない。

入力を高速送信したXCTestの1回は、文字が不足し、保存前の入力照合で停止した。検査側を1文字ずつ入力して値を照合する方式へ直して再実行し、保存拒否のケースに成功した。アプリの保存失敗とは区別する。

## 検証の境界

OSが自然に起動する長時間のBackgroundTask、Apple実サービス認証、外部による独立した暗号監査の完了は主張しない。既存の[残る作業と公開条件](shared-groups-design.md)を維持し、共有機能はDraftのままとする。
