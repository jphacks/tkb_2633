## 4. 不具合と変更理由

`controller-access.ts`は認証確認を待ってから、呼出元の配列・オブジェクトをそのまま渡していた。待機中に同じ入力参照が変更されると、タップ時と違う家事名・手順、別の読取期間・詳細対象を使っていた。`sharing-v2-events.ts`も、待機中に追加された操作や差し替えられたbuilderを後から使っていた。

`input-capture.ts`でJSON形式の入力を引き受け、認証・SQLite待機の前にコピーする。省略値を保持し、動的な日付範囲callbackは最新の地域を受けて評価する。非有限数・不正な型・過大な構造を拒否する。現在状態のbuilderは保持した関数を呼び、その結果もSQLiteの別のawaitへ進む前に保持する。

v2では、画面入口の確認後にSQLiteを待ち、その間に除名や新しい世代での再参加が保存されても、cached recordだけで古いDBに書けた。`workspace-session.ts`へ最新の参加状態・固定した世代・編集エラーの確認をまとめ、通常画面と保存処理で共用する。`sharing-v2-events.ts`が保存・投影前後にもこれを待ち、失効時は署名付き操作・Outbox・投影をまとめて戻す。権限エラー時に保持済みの内容を閲覧できる既存仕様も維持した。`workspaces.ts`の重複した判定は共通関数へ置き換えた。
