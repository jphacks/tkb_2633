# グループv2：統合製品仕様

2026-10-27受領の指示書（SHA-256は[監査](00-audit.md)に記録）を製品動作の正本とする。文中の「必須」は確定仕様、「判断待ち」は追加確認が必要な箇所である。実装状況は[進捗](05-progress.md)を参照する。

## 保護する境界

- 個人DB・個人履歴は共有DBと別。個人利用にログインは要求しない。
- グループの共有イベントにはOAuth、Google Task ID、Calendar本文・busy、APIキー、生PDFを入れない。
- 暗号・署名・因果関係・Outbox・Snapshot・冪等再送・世代分離を維持する。
- 端末時刻やサーバー到着順による暗黙の競合解決を行わない。
- v1で修正済みの保存・画面更新・認可のガードを維持する。
- 複数グループ管理は残すが、グループ間の予定競合計算は追加しない。

## グループと既定値

管理者はグループにつき1ユーザー。署名鍵を持つ所有端末と既存の所有権移譲方式は維持する。管理者であっても個人DB・本人のGoogle予定へアクセスする権限は生じない。

| 設定 | 家族 | 同居人 |
| --- | --- | --- |
| 家事単位の権限委譲機能 | 初期ON | 初期OFF |
| 担当者本人の期間前への変更 | 初期許可 | 初期許可 |
| 期間後への変更 | 管理者承認 | 初期許可、OFF可 |
| 管理者の指定を本人承認なしに固定 | 初期ON | 初期OFF |
| 前倒し自動承認 | 初期ON、OFF可 | 初期ON、OFF可 |
| 代行 | 初期許可、管理者が制限可 | 初期許可、管理者が制限可 |
| アプリ内の完了状況 | 初期ON、OFF可 | 初期ON、OFF可 |
| 完了プッシュ | 初期OFF、ON可 | 初期OFF、ON可 |

委譲機能をONにしても誰にも権限を付与しない。家事ごとに管理者が明示付与する。種別変更では、保存済みの通知・権限・表示設定を初期値へ戻さない。

## 4種類の家事

| UI上の種類 | 公開範囲 | 担当・完了 |
| --- | --- | --- |
| 全員共通 | グループ | 原則1人の実施でその家事回が完了 |
| 各人が実施 | グループ | 対象者それぞれに独立した完了状態 |
| 特定メンバー担当 | グループ | 指定者が担当、家族・同居人の双方で使用可 |
| 完全な個人家事 | 本人だけ | 個人DB・本人履歴 |

内部では公開範囲、担当ルール、完了条件、予定ルールを分離する。個人家事は共有ホーム・カレンダーに本人だけ重ね表示し、共有DBへコピーしない。共有への変更では公開される設定を確認し、過去の個人履歴は移さない。

## 共通の家事回と私的な推奨

共通の周期・基準日・家事回ID・実施可能期間は全端末で一致する。本人の忙しさ、個人家事、休日等を使う推奨日は、この共通枠の後で個別に計算する。私的な入力と推奨を共通ハッシュへ入れない。推奨日の変更で家事回IDを変えない。

本人はメイン端末を指定できる。その端末がCalendarのbusyを取得し、同一人物の承認済み端末だけへ必要な状態を同期する。通信差による一時的な推奨の差を許し、復帰時に再計算する。OS任せの即時同期は保証しない。

## Calendarと競合の情報量

FreeBusyの開始・終了だけを本人用に保持する。タイトル、場所、勤務などの内容を取得・推測しない。鮮度・取得範囲・認証主体を保持する。古い・未取得・オフラインでは「最新の予定を確認できません」とし、空き時間と同一視しない。

他人の日時指定に対する判定は、実際の権限付き指定・申請と結び付ける。一般の空き時間照会APIを作らない。返却内容は必要な競合有無／未確認だけとし、回数・対象・権限を制限する。競合がなければ通知不要。競合・未確認なら本人側で必要な警告を表示する。

18時以降の優先、勤務・授業・休憩による時間帯別負荷スコアは未決定である。

## 日時指定とルール

- 期限：指定日時までに完了。原則として前倒し可能。
- 実施日：指定日に実施。変更は前倒し承認などの設定に従う。
- 固定日時：指定した時刻に実施。原則、変更には承認が必要。
- 日付のみと、開始・終了時刻を持つ指定を区別する。

適用期間は「今回だけ」（初期値）、2週間、1か月、終了日指定、無期限。家事回ごとの例外を設定できる。重なる期間限定ルールは重複部分だけ置換し、前後を残す。周期変更後も今回限りの例外を一意に対応できれば残し、曖昧なら確認する。過去の完了履歴は変更しない。

優先順位は今回指定→期間限定→無期限→自動推奨。管理者固定、日時厳守、必須依存、権限を別途適用する。

## 変更の権限と申請

家族では、一般メンバーが原則自由に変えられるのは自分の担当。他人の担当は承認制だが、家事単位の委譲を可能にする。期間前は初期許可・OFF可、期間後は管理者承認とし、承認時に「今回だけ／今後にも適用」の範囲で共通期間を拡張する。同居人は期間前後を初期許可・OFF可とし、上位の固定・権限・本人承認は維持する。

管理者固定を本人が無断解除・変更することはできない。申請への回答は承認、拒否、代替日時。本人が管理者の代替案を承諾すれば確定し、再承認は要求しない。拒否・期限切れでは正式予定を変更しない。申請先は仮表示にとどめる。

前倒し自動承認は、禁止・日時厳守・同じ担当の固定家事との重複・期間外権限に従う。次回以降の共通周期を変えない。自動承認も履歴へ残し、プッシュは設定可能とする。

| 対象予定までの残り | 猶予 |
| --- | --- |
| 36時間超 | 24時間 |
| 24時間超〜36時間 | 12時間 |
| 12時間超〜24時間 | 6時間 |
| 6時間超〜12時間 | 3時間 |
| 1時間超〜6時間 | 1時間 |
| 1時間以内 | 新規申請不可 |

期限は`min(申請時刻＋猶予, 対象予定時刻−1時間)`。前倒し先の方が早ければ早い方を対象にする。日付のみはグループ時刻の23:59を計算基準とする。追加確認により、正式な申請・承認にはサーバー受付時刻を使う。オフライン中は送信待ち、期限後の到着は失効とし、元の記録時刻と履歴は保持する。

## 指定時の警告・拒否

| 状態 | 動作 |
| --- | --- |
| 負荷上限超過 | 「この日は家事の負荷が高くなっています。この日に指定しますか？」。取り消す／指定する。確認後は許可 |
| Calendar競合 | 「指定する時間帯にはカレンダーに予定が入っています。本当に指定しますか？」。取り消す／指定する。内容は指定者に公開しない |
| 同じ担当者の固定共有家事と時間重複 | 拒否。「この時間帯は別の家事を行う必要があります。別の時間帯を指定してください」 |
| 異なる担当者・同時刻 | その理由だけでは拒否しない |
| 日付のみの同日指定 | 時刻競合でなく負荷として評価 |
| 最近実施済み | 管理者へ「最近実施されていますが、もう一度指定しますか？」。確認後は指定可能 |

家族の管理者指定と衝突した個人家事は、自動生成・未固定・本人の期間内・他の固定予定に衝突しない場合だけ移動できる。同日内を先に探す。本人の固定家事は管理者でも動かせない。同居人は本人の許可制。理由と履歴を本人側へ残し、他人へ名前・内容を公開しない。追加確認により、自動移動は本人が設定した実施可能時刻帯の中だけとし、未設定なら候補の確認を求める。

## 担当、引き受け、代行

途中参加・担当変更は今回から／次回からを選択する。完了済みの家事回を維持する。退出した担当者の家事は再割当待ちとし、それまでは未担当の共有家事として扱う。

未担当の共通家事だけに引き受けを表示する。共有家事がなければ入口を出さず、「立候補」は作らない。解除は原則自由で未担当へ戻るが、管理者固定担当は申請を要する。

同時に引き受けた全員を暫定担当者とし、管理者が正式に解決するまで家事処理と完了を続行する。到着順で勝者を決めない。共通家事は誰かの実施で完了し、後の担当確定で実施者の履歴を削除しない。

代行は初期許可。制限時は承認待ちとする。本来担当、実際の実施者、登録者、実施日時、登録日時を別に記録する。担当者・管理者は登録可能、代行許可ONなら他メンバーも登録可能。取消は登録者または管理者に許可する。

## 完了、周期、仮想消化

実完了、日時厳守条件の未履行、未完了、再実施不要、仮想消化、代行・変更の承認待ちを区別する。異なる日に実施しても事実は保存し、指示を履行したかを別判定する。今実施／以前実施を選び、以前の場合は実施日時を入力する。記録日時は別に保持する。

共通期間は共通の基準から計算し、個人の完了で動かさない。全員共通は全体、各人実施は各人、特定担当は対象者に完了と再実施不要を適用する。個人家事は本人の履歴だけを使う。

2〜6日周期は実際の完了日から最低間隔を計算する。7日以上は対応する家事回を完了し、次の共通周期を維持する。日次は24時間間隔制限と同一視しない。

仮想消化を実完了イベントとして保存しない。未完了の過去回を残しながら次回の周期を進め、実完了日、家事回ID、周期基準、再実施不要期間、ルール版を区別する。

期限超過から5日間はホームの折りたたみ見出しから確認できる。5日後はホームの通常表示から外し、カレンダーを遡って過去完了できる。表示期限と仮想消化のタイミングは別である。

## 通知、同期、依存、Google Tasks

未担当の共通家事は全員を通知対象とし、引き受け後は担当者を主対象にする。他人担当の催促は原則送らない。共通家事の完了後は他メンバーの未完了通知を取り消す。未同期のオフライン端末に通知が残る可能性とOSの制約を明記する。個人・グループ・ユーザーのnamespaceとiOS通知数制限を維持する。

操作はその瞬間にローカル記録し、再送で操作時刻を作り直さない。独立項目は安全なら統合、同値は一致扱い、異なる同時日時は候補を残す。完了と変更が競合しても実施事実を失わせない。管理者へ復帰時などに解決カードを出し、解決も署名付きイベントにする。無関係な家事まで停止しないが、既存の安全停止を根拠なく緩和しない。履歴は委譲機能のON/OFFによらず見られる。

必須依存は守り、任意依存の衝突は警告する。Google Tasksは本人・作業領域・家事回の対応を保ち、認証済み本人の操作として共有完了へ反映する。既存の双方向完了・取消、削除との区別、未送信revisionの優先を不用意に変えない。

## 今回確定しないもの

時間帯別の負荷スコア、勤務・授業・帰宅後の休憩を推測したアルゴリズム、設備資源の排他制御、高度な即時プッシュ、グループ間の競合判定は追加しない。本番schema変更・main統合・Draft解除・一般公開は別途の明示承認を要する。
