# Phase 6後：モバイルUIと操作の回帰検査

2026-10-29、基点`25fdf5e`、`codex/encrypted-group-sharing`、[Draft PR #6](https://github.com/jphacks/tkb_2633/pull/6)。[Phase 6の開発検査](13-phase6-native-group-completion.md)の完了後、指定されたUIを調整した。本番v2の有効化、mainマージ、Draft解除は行っていない。

## 表示と操作

- ホームは「今日も1日頑張りましょう」。全件完了、または予定0件で19時以降なら「今日も1日お疲れ様でした」。0件では進捗の件数・割合・棒を表示しない。19時・日付変更・復帰で文言を更新するためにSchedulerを再実行しない。未完了があれば丸めても100%にはしない。
- ホームとカレンダーは、期限間近の未完了→その他の未完了→完了、それぞれ重い→普通→軽いの9段階。期限間近は「実際の今日が推奨日より後で、実施期間の終わりまで2日以下（超過も含む）」とした。選択した未来の日付を今日として優先順位を変えず、同順位は安定したIDで決める。
- 完了はSQLiteの終了を待たずチェック・進捗・順序を更新する。同じ瞬間の二重タップを防ぎ、書込失敗だけ元へ戻す。保存後の再読込失敗は「保存済み」として再読込だけを提供し、完了を二重保存しない。グループ切替後の古い応答も表示へ適用しない。
- 今日のカードは最小64pt、縦余白9pt。主文の可読性とタップ領域を維持する。「個人」「共有」「共有・日時指定」「推奨日前」「期限間近」の文字と控えめな色を併用する。共有の完了状態を隠す設定は引き続き尊重する。
- 通常リストの移動はReanimatedのlayout transition。仮想化されたv2のホームとカレンダーは`Animated.FlatList`の`itemLayoutAnimation`を使用する。共有カレンダーでは完了直後の点・棒も更新し、既に読める月には保存中だけ本文を増やしてカードを押し下げる処理を入れない。
- 設定の分類見出しに全件スイッチ、家事見出しに個別スイッチを追加。分類は有効件数／全件数を表示し、文字と矢印のどちらからも開閉できる。まとめた有効化は全件を検証して1トランザクションで保存し、周期不明の家電家事や他領域のIDを含めて部分保存しない。個別周期や履歴は保持する。
- 設定と説明は、同じ分類・見出し順の連結した仮想化ドキュメントへ変更。見出しから該当家事へ移動し、右側の分類バーで移動できる。戻るは下部へ固定し、タブバーの上ではsafe areaを二重に取らない。
- 設定の入力中データと保存キューを行ではなくドキュメントで保持する。画面外へ出て行が解放されても入力値・保存失敗を失わない。固定Back・Android Back・スワイプ離脱はいずれも保存を待ち、不正数値があれば該当箇所を示して離脱を止める。
- 説明の見出し直下に周期と目安時間を表示。元資料に時間のない家事には時間を捏造しない。各章の履歴・未完了記録、検索・分類・豆知識も保持する。
- 手順の数字は固定幅・等幅数字・本文と同じ行メトリクスで先頭行のbaselineを揃える。一般入力欄は段落用lineHeightを使わず、単一行を中央、複数行を上揃えとする。数値欄の専用配置は維持する。矢印の共通形状をBack・開閉・月移動・候補行へ適用した。
- 家電の製品名入力後の解析ページにも下部固定Backを設けた。通信中の中断と戻り先を保持する。iOSはキーボード回避、Androidは既存adjustResizeへ重ねて補正しない。ヘルプも実際の新しい操作へ更新した。

## Native互換性・データ・容量

Expo SDK 58の依存整合検査がReact Native 0.88.1を要求したため、`expo install`で0.88.0から互換パッチへ揃えた。lock内の同一バージョンの重複依存もnpmが整理した。Expo Doctorは20/20。

CNGで生成し、iOSは実機用Debugをbuild、Androidは接続端末に必要なarm64-v8aのDebugをbuildした。両方成功。既存と署名・bundle/package IDを照合して上書きインストールし、アンインストールしていない。インストール前後、起動前にAndroid94件・iOS107件のSQLite関連ファイルがすべてbyte一致した。これは201個のDBという意味でも、Keychainや全AppGroupをbyte比較したという意味でもない。起動後に既存の暗号化共有領域も読めた。

LiFlowアイコンは元の白い図形を参照し、組み合わせ全体の中心を調整するimagegen編集を使用した。最終指示の要点は「元の白いキャラクター・ブラシ・チェックリストの形を保ち、全体を少し右上へ動かしてキャンバス中央へ置く。青背景と円形safe marginを保ち、文字や枠を加えない」。成果物は`assets/images/liflow-icon.png`で、両OSの同一参照とAndroid insetは保持する。白い図形のbbox中心が各軸1%以内、全画素不透明、円形safe zone内であることを自動検査へ追加した。

容量対策は再生成可能な非対象ABIの中間生成物、今回のiOS ModuleCache、npm cacheに限定した。開発ツール、実機用生成物、元データと復旧用バックアップは保持し、内部空きは最終確認で約4GiB。外部ストレージが接続されていないため移動は行わなかった。
