# ホームの情報整理と共通の家事

2026-10-29。基点 `d8c6ade`。Phase 6後のUI再点検に続き、ユーザーとiOSシミュレーターの画面を見ながら合意したホームの変更。

## 表示と操作

- 見出しは「今日の家事」へ統一し、件数は進捗欄の1か所にまとめる。挨拶・件数・割合・細いバーをコンパクトにする。0件時の進捗非表示と、19時以降の挨拶の既存条件を保持する。
- 上部の3人アイコンから共有グループへ1タップで進む。個人、または「個人 ＋ 選択中のグループ名」を表示する。ホームの大きい共有切替帯を省き、他画面の既存の入口は保持する。
- 家事は薄い区切りのリストにする。左のチェックは完了操作、それ以外の行全体は説明への入口とする。右端に共通の青い矢印を置く。説明とチェックは独立したアクセシビリティ要素で、本文・矢印・余白を押しても完了操作は発火しない。押下中は行全体に薄い反応を付ける。
- 繰り返す分類名と「手順を見る」の文言を省き、登録済みの正の目安時間だけ「約○分」と表示する。時間不明の家電に推定値は加えない。個人と共有の混在時は、同色の1人アイコン（15pt）と、視認性を上げた3人アイコン（22pt）を同じ位置に表示する。読み上げでは出所を伝える。担当者・日時指定・期限・推奨日前など、判断に必要な情報は保持する。
- ゴミ出しもホームでは左チェックに揃える。カレンダーの既存の右側チェックと当日だけの非表示・復元は保持する。

## 並び順と今週・来週

「重い順 ⇅」を1回押すと「軽い順 ⇅」になる。期限間近の未完了→その他の未完了→完了の順を保ち、各段階の負荷順を反転する。同じ負荷内では既知の目安時間もその方向へ並べ、不明を0分とみなさない。設定は `expo-sqlite/kv-store` の端末内キー `liflow.home.load-order.v1` へ保存し、共有定義・Outbox・Schedulerの版や他メンバーの順番を変えない。保存失敗は表示する。

今週・来週では、同じ家事回を実施期間の毎日に並べず、推奨日に1回だけ並べて実施期間を添える。異なる周期の回は保持し、再計算で元の予定行が消えても記録済みの未来の完了を落とさない。今日の実施可能な家事と、カレンダーの日別表示は保持する。

## 同じ名前の家事

個人の情報をグループへ無条件にコピーせず、選択中のグループと個人の表示を合成する。同名の家事は1行にまとめ、グループ側の周期・負荷・有効状態・予定を使う。個人の元の定義は更新しない。グループ側で無効・削除になった場合や同名でなくなった場合は、個人の元の設定へ戻す。

名前はNFKCと前後空白だけを正規化する。部分一致で別の作業を同じものにしない。共有側に同名が複数ある場合は、勝手に1つの周期を選ばない。個人のアーカイブ済み定義は復活させない。

グループの完了・取り消しは、他メンバーの操作も含めて個人側へ反映する。共有側の正規の記録を再試行可能な根拠とし、個人DBにグループ・家事回・個人家事を識別するローカルの記録を保持する。同じ記録を再受信しても増殖せず、明示された取り消しだけを対応する記録へ適用する。記録が単に取得範囲にないことを取り消しとみなさず、元の独立した個人履歴を変更しない。名前・有効状態の変更後も、以前に対応した記録の取り消しを適用できる。

グループ保存後に個人側への反映が失敗した場合は、その旨と再試行を表示する。再試行は保存済みの共有操作を再発行せず、反映と読込だけを行う。個人側の保存後に読込だけ失敗した場合も、重複履歴を作らず読込を再試行する。画面描画だけで新しい共有操作を作らず、個人の定義・手順・OAuth情報を共有Outboxへ送らない。

既存v1では元から維持している個人Providerを再利用し、ライフサイクル処理やDB読込の所有者を増やさない。同じ `local-household` IDを持つ別DBを混同しないよう、操作の保存先と表示キーに出所を含める。個人だけの家事の説明・履歴は個人DBを参照し、共有の同一IDを誤って開かない。古い個人チェックが共通化後に実行された場合は保存を拒否する。

v2では本人の家事回と全員共通の家事回だけを個人側へ反映し、他人の各人実施用の回や未承認の代行を自分の完了としない。共通化した個人分を個人Overlay・日別件数・負荷から除き、同じ作業を二重計上しない。既存v1グループの自動変換はしない。

## 控えめな取り消し

完了の保存と再読込に成功すると、タブの上に小さい「完了しました　元に戻す」を約6.5秒表示する。一覧を押し下げず、操作部分は44pt以上確保する。画面を離れた古い通知や二重タップでは操作を再送しない。

個人・v1は保存と同じトランザクションで事実を捕捉し、ID・家事回・保存先・時刻・記録元を照合する。共有は自分の作成した操作IDだけを取り消し、別メンバーの有効な完了を消さない。v2でも同じ規則を使う。個人だけの家事をv2に重ねたときは、再読込で別の回が選ばれた場合にUndoを付けない。保存後の表示失敗は読込専用の復旧へ進める。

## 検証範囲

`home-ux.test.mjs` と `home-common-chores.test.mjs` に加え、既存のv2実SQLite画面検査を拡張した。異種OS用の画面配線、9段階の並び順、端末内保存・再起動・失敗、同一回の重複表示、保存した事実だけのUndo、元設定の保持と復帰、共通の完了・取り消し、権限喪失時のトランザクションのロールバック、古い操作の拒否、100回の同時同期、1,000件の反映済み履歴の再受信で件数分の読込・認可確認と書込を増やさないこと、保存後の読込再試行、個人と共有Outboxの分離を検査する。旧333機能契約を変更せず341へ拡張する。

iOS 27.0の既存「Housework QA」シミュレーターを使用し、データを初期化せず開発ビルドを更新した。更新前にSQLite関連3ファイルをコピー・hash照合し、インストール直後・起動前の一致も確認した。ローカル署名後にKeychain警告がないことを確認した。

画面から完了と小さいUndo、重い順／軽い順、プロセス再起動後の順番の保持、共有入口との往復を確認した。情報量・左チェックのリスト・青い矢印・個人と共有のアイコンはユーザーと見比べた。実際のv1グループでは個人7件と共有18件を合成した後、同名を共通化して18件となる表示を確認した。これを今回のiOS物理端末／Android実機の全条件PASSとは扱わない。

最終の自動検査はiOS条件2,233/2,233、Android条件2,233/2,233、Firestore Rules Emulator 71/71で失敗・skipは0。lint・型検査も成功。ソースとログの照合値は [証拠JSON](evidence/2026-10-29-home-ux.json) に記録した。mainマージ、本番Rules／schema変更、Draft解除は実行しない。グループ加入の手順削減と同一アカウントの別端末での自動参加は、今回のホーム変更へ含めない。
