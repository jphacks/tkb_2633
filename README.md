# 家事お知らせアプリ

生活の頻度と休日に合わせて家事の実施期間を作り、「何を・いつ頃・どうやって行うか」をアプリ内で確認できるiOS・Androidアプリです。家事データ、完了・未完了の記録、予定、ゴミ収集曜日は端末内SQLiteに保存します。

## 実装したMVP機能

- 初回設定：家事頻度、休日曜日、担当する家事、任意の前回実施時期
- 共通スケジューラ：周期、実施期間、休日、家事負荷、依存順を使った予定生成
- 初回実施日が不明な家事の負荷分散と、期限を過ぎた家事の再提案・継続表示
- 家事一覧・検索・有効／無効切り替え・手順・道具・注意点・所要時間の表示
- 家事ごとの周期、実施期間幅、負荷、休日優先、担当者、依存関係の編集
- 月間カレンダーと、完了日を基準にした次周期の再計算
- 完了・未完了の履歴と、端末内の家族・同居人登録および担当分担
- ゴミ収集区分の曜日登録、編集、削除、次回収集日の表示
- iOS・Androidの次の家事ウィジェットへのスナップショット更新
- 洗濯の基本の干し方（外干し・部屋干し・どちらでも）の保存

初期の家事一覧と頻度モードごとの周期は、企画書で未確定のため調整用のたたき台です。家事詳細から周期を変更できます。初期の周期案を正式な推奨値として扱わないでください。

## 後から接続する機能

- **天気**：予報取得・場所の選び方・家事の調整ルールは未接続です。現在の予定は天気で変わりません。洗濯の干し方は手動設定です。
- **通知**：端末内通知の汎用ゲートウェイと9:00の初期値を用意しています。通知許可を求めたり、予定の通知を予約したりする機能はまだ接続していません。
- **ウィジェット**：両OS向けに登録し、次の家事を渡します。表示サイズや操作などは後から調整できます。
- **ゴミ収集日の例外**：祝日・臨時変更などのルールと保存形式は未確定です。登録曜日どおりの通常日だけを表示します。
- **家電AI**：公式資料の解析結果を受け取る契約のみ用意しています。AI APIと資料の取得・解析は未接続です。
- **家族間同期**：世帯メンバーと担当はこの端末内で管理します。アカウントや同期先サーバーは未選定です。

これらはオフラインの家事管理から分離しています。外部連携の失敗で端末内の家事機能が止まらない構成です。

## 技術構成

- Expo SDK 58、React Native、TypeScript、Expo Router
- Expo SQLite、Expo Notifications、Expo Widgets
- iOS / Androidのローカル開発ビルド

## ローカルで起動する

### 必要なもの

- Node.js 22.13以上
- iOS：XcodeとiOS Simulator
- Android：Android Studio、Android SDKとAndroid Emulator

### 初回

```sh
npm ci
npm run ios       # iOS Simulatorで開発ビルドを作成・起動
# または
npm run android   # 起動中のAndroid Emulatorで開発ビルドを作成・起動
```

SQLiteとウィジェットを含むネイティブ開発ビルドが必要です。Expo Goでは確認できません。初回ビルドはiOS/AndroidのSDK部品を取得するため時間がかかる場合があります。
`npm run ios` は `ios-build.xcconfig` を使い、Xcode 27の明示的モジュール生成に関する互換性問題を避けます。

### 2回目以降

```sh
npm start
```

開発サーバーが起動したら、ターミナルで `i`（iOS）または `a`（Android）を押して開発ビルドを開きます。TypeScript/JavaScriptの変更は通常、ネイティブアプリの再ビルドなしで反映されます。

`npm ci` の後処理では、日本語を含む作業フォルダーでCocoaPodsがHermesのパスを扱えるよう、`node_modules`内のpodspec出力をUTF-8に揃えます。

ネイティブ依存関係または `app.json` の変更後は、ネイティブプロジェクトを作り直します。

```sh
npx expo prebuild --clean
npm run ios       # または npm run android
```

生成される `ios/` と `android/` は `.gitignore` 対象です。設定は `app.json` とソースに置き、生成物はコミットしません。

## ローカル確認とCI

```sh
npm run check     # lint、TypeScript型チェック、スケジューラ単体テスト
npm run doctor    # Expoの依存関係・設定診断
npm test          # 単体テストだけ実行
```

GitHub ActionsはPull Requestおよび `main` へのpushで `npm ci` と `npm run check` を実行します。
