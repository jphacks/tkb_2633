# 家事お知らせアプリ

生活の頻度と休日に合わせて家事の実施期間を作り、「何を・いつ頃・どうやって行うか」をアプリ内で確認できるiOS・Androidアプリです。家事データ、完了・未完了の記録、予定、ゴミ収集曜日は端末内SQLiteに保存します。

## 実装したMVP機能

- 初回設定：家事頻度、休日、管理する家事、前回の実施時期、天気用市区町村の検索と候補確定
- 4つのタブ：ホーム、カレンダー、家事の説明、家電の説明
- 共通スケジューラ：周期、実施期間、休日、家事負荷を使った予定生成
- 初回実施日が不明な家事の負荷分散と、期限を過ぎた家事の再提案・継続表示
- 家事説明：ホームやカレンダーで選んだ家事の手順・道具・注意事項
- 設定から開く家事別の周期、実施期間幅、負荷、休日優先、洗濯の干し方
- 月間カレンダーと、完了日を基準にした次周期の再計算
- 全体または家事ごとの完了・未完了履歴
- ゴミ収集区分の曜日登録、編集、削除、次回収集日の表示
- iOS 2×2・Android 2×2の「今日の家事」ウィジェット（Schedulerの順で最大3件）
- 洗濯の基本の干し方（外干し・部屋干し・どちらでも）の保存
- 入力した地域名を使った Open-Meteo 予報取得と、今後7日以内の洗濯予定の制約付き調整

初期の家事一覧と頻度モードごとの周期は、企画書で未確定のため調整用のたたき台です。設定から家事ごとの周期を変更できます。初期の周期案を正式な推奨値として扱わないでください。

## 後から接続する機能

- **通知**：初回設定と設定画面で通知のON/OFFを選べます。OS許可はユーザーがONにした時だけ要求します。通知を予約する具体的な日時・再通知ルールは未決定です。
- **ウィジェット**：両OS向けに登録し、今日の家事をSchedulerの優先順で最大3件表示します。
- **ゴミ収集日の例外**：祝日・臨時変更などのルールと保存形式は未確定です。登録曜日どおりの通常日だけを表示します。
- **ゴミ予定の個別非表示**：特定の収集区分・日付だけを非表示にし、後から再表示できます。曜日ルールや次回以降の収集日には影響しません。
- **家電AI**：メーカー・製品・型番からメーカー公式情報を確認し、公式説明書を構造化解析するポータブルAPIを用意しています。安定IDを持つ家電親データへ解析結果全件を保存し、周期ありtaskだけを既存Schedulerへ追加します。周期なしtaskは家電詳細に保存し、自動予定には入りません。再解析は確認後にAI由来情報を更新し、完全一致したtaskの周期overrideと実施履歴を引き継ぎます。APIキーが未設定の環境では実解析は利用できません。

通常の家事管理はオフラインで動きます。天気連動は初回設定または設定画面で市区町村を入力すると候補を自動検索し、選んで確定した場合だけ Open-Meteo に接続します。候補は日本の市区町村と都道府県を表示します。取得に失敗した場合は通常の予定を使います。入力した市区町村名を地名検索APIへ送信し、選んだ地域名と検索地点の座標を端末内に保存します。端末の位置情報は使いません。設定画面からいつでも解除できます。洗濯の干し方は手動設定です。

家電AIの解析だけは、ユーザーが明示的に検索を実行した場合にAPIサーバーとOpenAIへ接続します。製品同定・説明書検索はメーカー公式ドメインに限定します。家電・家事の登録情報はSQLiteに保存され、アカウントや同期先サーバーは使いません。

## 技術構成

- Expo SDK 58、React Native、TypeScript、Expo Router
- Expo SQLite、Expo Notifications、Expo Widgets
- iOS / Androidのローカル開発ビルド

## ローカルで起動する

### 必要なもの

- Node.js 22.13以上
- iOS：XcodeとiOS Simulator
- Android：Android Studio、Android SDKとAndroid Emulator

### 初回

```sh
npm ci
npm run ios       # iOS Simulatorで開発ビルドを作成・起動
# または
npm run android   # 起動中のAndroid Emulatorで開発ビルドを作成・起動
```

SQLiteとウィジェットを含むネイティブ開発ビルドが必要です。Expo Goでは確認できません。初回ビルドはiOS/AndroidのSDK部品を取得するため時間がかかる場合があります。
`npm run ios` は `ios-build.xcconfig` を使い、Xcode 27の明示的モジュール生成に関する互換性問題を避けます。

### 2回目以降

```sh
npm start
```

開発サーバーが起動したら、ターミナルで `i`（iOS）または `a`（Android）を押して開発ビルドを開きます。TypeScript/JavaScriptの変更は通常、ネイティブアプリの再ビルドなしで反映されます。

`npm ci` の後処理では、日本語を含む作業フォルダーでCocoaPodsがHermesのパスを扱えるよう、`node_modules`内のpodspec出力をUTF-8に揃えます。

ネイティブ依存関係または `app.json` の変更後は、ネイティブプロジェクトを作り直します。

```sh
npx expo prebuild --clean
npm run ios       # または npm run android
```

生成される `ios/` と `android/` は `.gitignore` 対象です。設定は `app.json` とソースに置き、生成物はコミットしません。

## ローカル確認とCI

```sh
npm run check     # lint、TypeScript型チェック、スケジューラ単体テスト
npm run doctor    # Expoの依存関係・設定診断
npm test          # 単体テストだけ実行
```

GitHub ActionsはPull Requestおよび `main` へのpushで `npm ci` と `npm run check` を実行します。

## 家電AI APIをローカルで使う

OpenAI APIキーはアプリの `.env` や `EXPO_PUBLIC_*` に入れず、APIサーバーの `.env.server` だけに設定します。

```sh
cp .env.server.example .env.server
# .env.server の OPENAI_API_KEY にサーバー用キーを設定
npm run api:dev
```

APIが起動したら `http://localhost:8787/health` を開いて状態を確認します。`aiConfigured` が `false` の場合は実解析を行えません。iOS Simulatorは初期値の `http://localhost:8787`、Android Emulatorは `http://10.0.2.2:8787` を使います。実機では同じWi-Fi内の開発MacのIPを使い、Expo側の環境変数 `EXPO_PUBLIC_APPLIANCE_CARE_API_URL=http://<開発MacのIP>:8787` を設定してアプリを再起動します。APIサーバーはポート8787で待ち受けます。

HTTP接続は開発用です。公開環境で使う場合はHTTPSでAPIを公開し、APIキーはホスト側の環境変数管理機能に登録してください。

家事一覧の「家電を公式資料から調べる」から、Dyson V12 Detect Slim（SV20）を初期入力として試せます。アプリから検索するとAPIは製品確認、公式説明書の特定、AI解析を順番に実行します。検索と解析にはインターネット接続とOpenAI API利用料が必要です。通常の家事管理と保存は端末内だけで動作します。

APIサーバー単体の疎通はAPIキーなしでも確認できますが、その場合は解析リクエストに `503` を返します。`.env.server` はGit管理対象外です。実機E2Eを行う場合は、開発Mac上のAPIサーバーに接続できることと、キーがAPIサーバー側で設定済みであることを確認してください。
