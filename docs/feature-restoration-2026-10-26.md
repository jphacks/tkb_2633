# ゴミ機能の復旧と、前回不明の家事を有効化する処理の検証

確認日: 2026年10月26日（日本時間）。修正前のmain: `3b799a0`。

## なぜ機能がなくなって見えたか

以前の実装はGit履歴に残っていました。

| コミット | 実装内容 |

| `14bf39d` | 家電解析の自動保存、メーカー周期の自動登録、日本語カテゴリ候補 |
| `68f05ee` | ゴミの毎週・隔週・毎月とカレンダー表示 |

| `9aa377b` | 日本語のゴミ区分検索 |

これらは `fix/appliance-ai-app-integration` 系統にあり、現行mainの祖先ではありませんでした。mainは `c155a79` を親とする別系統の変更から進んでおり、機能コミットが統合されていません。確認できた履歴には「mainからこれらを明示的に削除したコミット」はありません。別ブランチの実装をmainへ引き継げていなかった統合漏れです。

前回はmainの現状だけを見て「未搭載」と報告し、以前の実装とブランチ履歴まで追っていませんでした。これは確認不足でした。今回、最近のScheduler・Google同期・Widget修正を保った最新mainへ、欠けていた機能を組み込み直しました。

## 復旧した機能

### ゴミ収集日

- 毎週: 複数曜日。
- 隔週: 曜日1つと、次に収集する週を選択。基準日から14日ごと。
- 毎月: 1〜31日を指定。その日が存在しない月は月末。
- 初期設定に6段階目として追加。登録・編集・削除・次回予定の確認、設定せずに始める操作に対応。
- 初期設定と設定画面は同じ `WasteScheduleEditor` を使用。入力ごとのひらがな候補検索、選択して追加する手順を共通化。
- 収集曜日は7個を横一列に配置。
- 毎週の名前はカレンダーの曜日見出しを白地・橙色の枠で囲んで表示。
- 隔週・毎月は対象日を同じ色の枠で囲んで表示。週ごとに行を組み、名前の有無で日付の列がずれない配置。
- 月送りでも選択日・下の家事を保持。選択日が見えていない月では青い日付の案内も表示。
- 「次の収集日」は閉じた状態から見出しで開閉。「今回は表示しない」と再表示も維持。
- カレンダーで先の月に移動した場合も非表示指定を反映するよう、35日より先の例外キーも読み込み。
- 保存中は編集・削除などの重複操作を抑止。周期、曜日、実在日、名称長を共通の保存規則で検証。

### DBの互換性

スキーマをv17へ更新しました。旧ゴミ機能ブランチはv13で周期列を追加していましたが、mainは別の意味でv13を使用していました。列の存在を確認し、現行v16の毎週データと、旧v13の隔週・毎月データの両方を維持して移行します。名称・曜日・基準日・非表示指定・履歴を削除する移行ではありません。

### 家電解析

同じ未統合系統にあった機能も復旧しました。

- verifiedの解析結果を自動保存し、メーカー周期ありの項目を選択操作なしで予定へ登録。
- 周期なしの項目も説明・手順・出典を保存。周期を捏造せず、予定へは入れない。
- 日本語でカテゴリ候補を検索して選択。表示は日本語、保存・API送信は英語ID。
- 解析結果の見出しから保存した家電詳細へ移動。
- 解析画面で周期を変更して保存。家電IDを維持し、重複する家電を作らない。
- 周期欄を空にした際、古いユーザー周期を保持してしまう経路も修正。メーカー周期があれば推奨へ戻し、なければ周期未設定・予定なしに戻す。
- 周期未設定のため無効だった項目へ周期を設定した場合は有効にできる。ユーザーが周期ありの家事を手動で無効にした設定は再解析でも保持。
- Web版でAIへ送信しない処理を維持。APIのモデル・プロンプト・認証処理は変更していない。

## 家事の有効化で見つけた不具合と修正

### 1. 前回不明・無効からの有効化

初期設定で無効にした家事は、前回実施が空でも `initial_pending=0` でした。その後の有効化は定義のenabledだけを変更するため、初回予定を生成しても予定日がstateに保存されない経路がありました。翌日の再読込で初回日が動き、カードや期限超過の扱いが不安定になります。

- 前回不明の状態を、有効・無効とは独立して保持。
- 切り替えと個別設定の有効化を同じ更新処理へ統一。
- 未着手の家事を再有効化するときは、今日から初回予定を作る。実際の完了履歴・周期の基準は保持。
- 既存の壊れたstateも読み込み時に修復。表示済みの初回予定がある場合は、その日付を引き継ぐ。
- 予定のJSONが変わらない場合でも、未保存の初回日を保存できる処理に変更。
- 初回予定日の保存後は、返すSnapshotのstateにも同じ日付を反映。

修正前の再現テストでは、切り替え・個別設定とも `initial_pending` が0のままで失敗しました。追加の既存データ再現でも、10月26日の初回予定が再読込で10月27日へ動くことを確認し、修正後は元の日付を保持しています。

### 2. 無効にした完了カードが残る

日付のカード選択が完了履歴を家事の有効状態で絞らず、無効化後にも完了カードを再構成していました。

- ホーム・カレンダー・Widget・通知で、有効で未アーカイブの家事だけを予定表示の対象にする。
- 履歴そのものは保持。
- 無効化前の古いカードから完了要求が遅れて来ても、新しい完了として受け付けない。

## 検証

### 自動テスト

- `npm run check`: lint・型チェック・265テスト。
- UTCとAsia/Tokyoの両方で全テスト。
- 20家事×3頻度モードで「無効・前回不明→有効化→周期変更→再読込」。
- 周期1/2/7/17/30/90/180/3650日、翌日、長期間無効、古いstate、完了・取り消し、無効化・再有効化、1日1枚の表示。
- 実TSXの入力・イベントからRepository/SQLiteへの保存までを通す画面テスト。Nativeのレイアウトとアニメーション時間はこのテストでは再現しないため、iOS操作も併用。
- ゴミの週・隔週・月末・うるう年・非表示・再表示・編集・DB再読込・不正入力・旧DB移行。
- 家電解析のAPI結果をテスト用応答に置き換え、自動保存から実Schedulerへの登録・周期変更・解除を検証。
- 家事の分類・ひらがな見出し検索・豆知識・詳細からホーム／カレンダーへの戻り先。
- 横棒／点の0件消去、1〜5/6〜9/10以上の色、最大5点、未来分の完了がその日だけの件数を減らすこと。
- 設定の本文が上端固定・枠内にクリップされ、閉じた操作要素を隠すこと。
- 既存のGoogle双方向取り消し、期限超過、天気、Widgetの回帰テストも実行。

### iOS実操作

専用シミュレーター **Housework QA / iOS 27** で確認しました。

1. 「びん」を隔週木曜・10月29日開始で保存。
2. 「粗大ごみ」を毎月31日で保存。SQLiteの周期・基準日も確認。
3. 検証DBをバックアップ後、初期設定フラグを戻し、6段階を実操作。
4. 全家事を無効・前回不明で進め、初期設定のゴミ収集日で毎月28日へ編集して完了。ホーム0件を確認。
5. フローリングを有効・17日周期に変更。ホームに未完了カード1件。
6. 完了→1件完了、取り消し→未完了1件。再起動後も1件表示と設定の保持を確認。
7. カレンダーで週の見出しに可燃ごみ、10月28日に粗大ごみ、29日にびんを表示。日付タップでは展開せず、翌月へ送っても選択日を維持。11月はびんが12日・26日、粗大ごみが28日。

検証DBの実施履歴と家電説明はバックアップを保持しています。普段のシミュレーターのDBは初期化していません。

### Web

ローカルWebで「かん」検索→缶選択→毎月31日→保存→再読込を操作し、月次設定と初期収納を確認。静的exportも確認しました。

今回の家電自動保存の回帰はテスト用API応答で検証しました。今回あらためてGoogleの実アカウント認可やAndroid実機試験を完了した、という意味ではありません。

## 再発を検知する仕組み

- `docs/feature-contracts.json` に15機能の必要な回帰テストを登録。
- `npm test` の前に必要なテストファイル・ケースが存在するか確認。対応テストだけが消えた場合も失敗。
- その後、計算だけでなく画面からの入力・保存を含むテスト本体を実行。機能の呼び出しや初期設定の段階が欠ければ失敗。
- 初期設定を仮想的に6段階から5段階へ戻す変異テストで、操作テストが欠落を検出することも確認。
- GitHub CIにも必要テストの独立した確認を追加。
- `AGENTS.md` に、既存機能の契約確認・ブランチ照合・テストを弱めて通さない規則を追加。

この対象の機能削除・統合漏れを検知するための仕組みです。将来追加する機能も契約と操作テストへ追加して維持します。
