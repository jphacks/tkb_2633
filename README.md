# 家事お知らせアプリ

> **家事の「何を・いつ頃・どうやって」を、できるだけ自分で管理しなくてよくするアプリ。**

生活スタイル、休日、家事の負荷、天気などを考慮して家事の予定を自動で組み立てます。

さらに、掃除機などの家電については、メーカー名・製品名・型番から**メーカー公式情報と公式説明書を確認し、AIでお手入れ方法を構造化**します。

通常の家事管理は端末内で完結し、インターネット接続がなくても利用できます。

---

## 解決したい課題

家事には、単に「やる・やらない」だけではなく、

- 何をやればいいのか分からない
- どのくらいの頻度でやればいいのか分からない
- 今日やるべきなのか、数日ずらしてもいいのか分からない
- 休日にまとめたい
- 家事が同じ日に集中すると負担が大きい
- 洗濯は天気によって予定を変えたい
- 家電のお手入れ方法や周期を説明書から探すのが面倒

といった問題があります。

一般的なToDoアプリでは、ユーザー自身が予定を考え、期限を設定し、管理し続ける必要があります。

このアプリでは、**家事そのものだけでなく「家事を管理する負担」も減らすこと**を目指しています。

---

# 主な特徴

## 1. 家事を自動で分散するScheduler

家事ごとに、

- 実施周期
- 実施できる期間
- 家事の負荷
- 休日優先
- 前回の実施日
- 家事同士の依存関係

を持ち、共通のSchedulerが予定を生成します。

例えば、

- 重い家事が1日に集中しない
- 休日に向いている家事を休日付近へ配置する
- 前回いつ行ったか分からない家事を初回から分散する
- 期限を過ぎた家事も消さず、現在の負荷に合わせて再提案する
- 実際に完了した日を次回周期の基準にする

といった処理を自動で行います。

予定日は固定された「締切」ではなく、**ある程度動かせる実施期間**として扱います。

---

## 2. 天気に合わせて洗濯予定を調整

ユーザーが設定した市区町村を使ってOpen-Meteoから天気予報を取得し、今後7日以内の洗濯予定を調整します。

外干し可能な候補日は、

- 降水確率
- 降水量
- 天気コード
- 元の家事実施期間
- 1日の家事負荷
- 家事の依存関係

を確認したうえで選択します。

天気APIが利用できない場合でも、通常のSchedulerによる予定はそのまま利用できます。

端末のGPSや位置情報権限は使用せず、ユーザーが入力・選択した市区町村だけを利用します。

---

## 3. 型番からメーカー公式説明書をAI解析

家電のお手入れは、一般的なAI知識だけで回答させません。

次の流れで処理します。

```text
メーカー名・製品名・型番
        ↓
メーカー公式情報から製品を確認
        ↓
対象型番の公式説明書を特定
        ↓
公式PDF / 公式資料をAIで解析
        ↓
お手入れ項目・手順・注意事項・周期・出典を構造化
        ↓
ユーザーが内容を確認
        ↓
アプリへ保存
        ↓
周期がある項目だけSchedulerへ登録
```

製品同定と説明書検索では、メーカー公式ドメインだけを採用します。

AIには、メーカー資料に書かれていない周期を推測させません。

例えば説明書に、

```text
「定期的に確認する」
```

としか書かれていない場合、

```text
30日に1回
```

のような数値周期を勝手に生成せず、

```text
定期予定なし
```

として保存します。

公式資料のURLやページ情報も保持し、ユーザーが元資料を確認できます。

# 家電AIの実API検証

AI機能については、単に「それっぽい回答が出るか」ではなく、実際の公式説明書に対する人力の正解データと比較しました。

対象：

```text
Dyson V12 Detect Slim
型番: SV20
公式日本語取扱説明書
```

GPT-5.5を使用し、実際のアプリと同じAPI経路で3回E2E検証しています。

| 指標 | 結果 |
|---|---:|
| E2E成功 | 3 / 3 |
| 製品同定 | 3 / 3 |
| 正しい公式説明書 | 3 / 3 |
| Task Recall | 10 / 10 × 3 |
| Task Precision | 10 / 10 × 3 |
| 周期判定 | 10 / 10 × 3 |
| 主要手順 | 38 / 38 × 3 |
| 安全情報 | 33 / 33 × 3 |
| 出典 | 10 / 10 × 3 |
| 根拠のない生成 | 0 |

数値周期がメーカー資料に存在したのはフィルター洗浄の「約1か月」のみで、他のお手入れ項目には根拠のない周期を生成しませんでした。

より低コストなモデルも比較しましたが、手順や安全情報の欠落が確認されたため、現在は精度を優先してGPT-5.5を採用しています。

# デモで確認できる流れ

```text
1. 初回設定
   ↓
2. 生活スタイル・休日・管理する家事を設定
   ↓
3. Schedulerが家事予定を自動生成
   ↓
4. ホーム / カレンダーで予定を確認
   ↓
5. 家事を完了
   ↓
6. 実際の完了日から次回予定を再計算
```

洗濯では、

```text
地域設定
↓
天気予報取得
↓
条件を満たす日に洗濯予定を調整
```

家電では、

```text
メーカー・製品名・型番入力
↓
製品確認
↓
公式説明書解析
↓
お手入れ方法を確認
↓
家電へ保存
↓
周期あり項目だけ予定へ追加
```

という流れを確認できます。

## 部分実装

### 通知

初回設定と設定画面に通知ON / OFFを実装しています。

OSの通知許可は、ユーザーが通知を有効にした場合だけ要求します。

通知を送る具体的な日時、再通知、延期ルールはまだ確定していないため、通知予約処理は未接続です。

### ゴミ収集日の例外

通常の曜日ルールは利用できます。

祝日や自治体ごとの臨時変更などの例外ルールは未実装です。

---

## MVP対象外

- アカウント
- 家族間同期
- 複数端末同期
- クラウド上の家事データ保存

通常の家事データは端末内SQLiteに保存します。

# 画面構成

主な画面は4つのタブで構成されています。

### ホーム

今日・近いうちに行う家事、ゴミ収集日、完了操作などを表示します。

### カレンダー

月間予定と、複数日にまたがる家事の実施可能期間を確認できます。

### 家事の説明

選択した家事について、

- 手順
- 必要な道具
- 注意事項
- 履歴

を確認できます。

### 家電の説明

登録した家電ごとの、

- お手入れ項目
- メーカー指定周期
- 定期予定なし項目
- 手順
- 注意事項
- 公式出典
- 再解析

を確認できます。

# アーキテクチャ

通常の家事機能を、外部サービスなしでも動作できるようにしています。

```text
┌─────────────────────┐
│     React Native UI  │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│   Domain / Scheduler │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│    Expo SQLite       │
└─────────────────────┘
```

外部機能は別レイヤーとして接続します。

```text
                 ┌───────────────┐
                 │   Open-Meteo  │
                 └───────▲───────┘
                         │
UI → Domain → Feature Ports
                         │
                 ┌───────▼───────┐
                 │ Appliance API │
                 │    OpenAI     │
                 └───────────────┘
```

外部APIが失敗しても、基本的な家事Schedulerと保存機能は動作します。

# 家電AIの構成

```text
App
 │
 ▼
Appliance Care API
 │
 ├─ Product Resolver
 │    └─ メーカー公式情報だけから型番確認
 │
 ├─ Manual Resolver
 │    └─ 対象製品の公式説明書を特定
 │
 └─ Manual Analyzer
      └─ OpenAI Responses API
          ├─ PDF input
          ├─ Structured Outputs
          └─ Evidence validation
```

解析結果はそのまま自動登録せず、

```text
AI解析
↓
draft
↓
ユーザー確認
↓
保存
```

の流れを取ります。

# 家電AI APIを起動する

OpenAI APIキーはアプリ側へ保存しません。

`.env.server`を作成します。

```sh
cp .env.server.example .env.server
```

その後、

```text
OPENAI_API_KEY
```

をサーバー側の環境変数として設定します。

APIサーバー：

```sh
npm run api:dev
```

デフォルト：

```text
http://localhost:8787
```

health check：

```text
http://localhost:8787/health
```

---

## Simulator / Emulator

iOS Simulator：

```text
http://localhost:8787
```

Android Emulator：

```text
http://10.0.2.2:8787
```

実機の場合は、開発Macと同じネットワークからアクセス可能なURLを指定します。

例：

```sh
EXPO_PUBLIC_APPLIANCE_CARE_API_URL=http://<開発MacのIP>:8787
```

公開環境ではHTTPSを使用し、OpenAI APIキーはホスティング環境側のsecret / environment variableとして管理してください。
