# ゴミ収集日・設定の修正と機能確認

確認期間: 2026年10月25日〜26日（日本時間）。基準: main `02e7753`。

## 結論

指定されたゴミ検索・収集日一覧の収納・設定のアニメーションを修正し、iOSシミュレーターとWebで操作確認しました。確認中に見つけたWidgetの読み込み先と完了行の表示も修正しました。

主要なローカル操作、実AI解析、Widgetからの完了、iOSへのローカル通知の配信を確認できました。ただし、Google実アカウント連携、Android実画面、実機バックグラウンドは今回の確認済み範囲に含みません。全機能が全環境で合格した、という結論ではありません。

## 全修正内容

### ゴミ収集日

- 「今回は表示しない」は既存の手動例外処理です。その区分・日付だけを隠し、次回以降は保ちます。再表示もできます。祝日の自動振替とは区別しました。
- 古い「例外日について」の注意カードを削除し、architectureの説明も現行処理に合わせました。
- 自由入力だけだった収集区分を、文字入力ごとに候補を表示する形式にしました。通信不要の端末内検索です。
- 32区分の候補と読み・別名を用意し、「かね→可燃ごみ」「びん」「かん→缶」などに対応しました。カタカナ、半角、ゴミ／ごみも正規化します。
- 自治体独自の名前も明示的に選んで保存できます。候補選択と曜日選択が済むまで追加ボタンを無効にしました。
- 編集では既存の名称を保持します。削除時のエラーを表示し、非表示・再表示の処理中は重複操作を防ぎます。
- 「次の収集日」は初期状態で閉じ、見出し行を押すと開き、もう一度押すと閉じます。
- 保存する曜日の範囲、名称長、実在する日付を検証します。

変更: `src/app/waste.tsx`、`src/features/waste/waste-types.ts`、`contracts.ts`、`repository.ts`、`docs/architecture.md`。

### 設定の開閉

- 本文の上端・左右を固定し、親の高さが変わっても本文が移動しないようにしました。枠の内部を上から表示し、閉じる際は下から収納します。
- 高さの測定処理をJSXの外へ出し、Reanimatedのinline-style警告を避けました。
- 普段のローカルcheckoutには `SlideInDown` / `SlideOutUp` を使う古い本文移動が残っていました。変更前を退避し、設定画面のこの部分だけを共有コンポーネントに差し替えました。既存のGoogle連携・通知設定等のローカル変更は維持しました。
- 開閉を録画し、連続フレームで本文が見出しを突き抜けないことを確認しました。

変更: `src/components/accordion-section.tsx`。ローカル側では既存 `settings.tsx` の旧コンポーネントも置換。

### 確認で見つかったWidgetの不具合

- 共通の `NextChoreWidget.ts` が、Native用の `.ios.tsx` / `.android.tsx` より先に解決され、何もしないfallbackが使われていました。iOSで「予定なし」になる症状を再現しました。
- fallbackを `.tsx` へ変更し、Metroが各platformの実装を選ぶようにしました。実Metro resolverで、修正前はiOS・Androidが失敗、修正後は3platformすべて成功することを確認しました。
- 未完了が3件以上残っている場合も、完了した行を1件表示枠に残し、チェックの変化が見えるようにしました。
- iOSのホーム画面へ実Widgetを追加し、家事表示→丸を押す→アプリ側の完了件数更新→Widgetにチェックを保持、まで確認しました。

変更: `src/platform/widgets/NextChoreWidget.tsx`、`src/features/widgets/today-widget-snapshot.ts`、対応テスト。
