# 個別設定の自動保存・共通文字階層・追加検証

2026年10月26日。開始時のmainは `356520b0fed0083c49e4a3be6850f0658f70e8fc`。専用worktreeの `codex/autosave-typography-audit` で修正した。

## 依頼された変更

### 家事の個別設定

- 通常の「個別設定を保存」ボタンを削除。
- 有効・無効、負荷、休日優先、干し方は操作直後に保存。
- 周期と期間幅は450ms入力が止まった時点、または入力終了時に保存。戻る操作では保存を待ってから移動する。
- フォーカス離脱、バックグラウンド移行でも保留中の有効な変更を保存する。
- 全角数字を受け付ける。範囲外、小数表記、指数表記、文字混在はDBへ書き込まない。周期は1〜3650日、期間幅は0〜14日。
- 入力途中の空欄で0日を保存しない。周期を空欄のまま入力終了すると、組み込みの初期値またはメーカー推奨へ戻る。メーカー周期のない家電は周期未設定・無効へ戻る。
- ユーザーが明示的に無効にした家電は、周期変更や推奨周期へのリセットで勝手に有効に戻さない。
- 保存中・保存済み・失敗を表示。失敗時だけ再試行ボタンを表示し、入力内容を維持する。
- ヘルプの個別設定の説明も自動保存に合わせた。

生活リズムとカレンダー表示の一括設定は、今回の個別設定の自動保存とは別の既存操作を維持している。

### ゴミ入力・クレジット

- ゴミの種類の入力例を「ゴミの種類（例：可燃ゴミ）」へ変更。かな検索・候補選択・毎週／隔週／毎月は維持。
- クレジットは他の設定と同じ折りたたみ部品を使用。初期状態は見出しのみで、開閉できる。
- ローカルSQLiteについての文章をクレジットの下、設定画面の最後に移動。
- 天気と地域検索の近くにある出典表示とリンクは維持。

### 文字と余白

`src/components/planner-typography.ts` にサイズと行間を共通化し、ホーム、カレンダー、家事一覧・説明、家電一覧・説明・解析、個別設定、設定、初期設定、履歴、ヘルプへ適用した。

## 追加調査で修正した処理

| 箇所 | 問題または再現した競合 | 修正 |
| --- | --- | --- |
| 個別設定の更新 | 画面を開いた時点の家事全体を保存すると、後で更新された別項目を置き換え得る | 最新DB行へ編集項目だけ反映する部分更新 |
| 連続編集 | 数値の入力途中や遅い保存中の変更が競合する | 保存を直列化し、待機中の変更を統合。最後の値を保持 |
| 同値の保存 | 変更がなくてもDB書き込み・予定再生成を行う | 変更がなければ書き込みとキャッシュ無効化を省略 |
| 保存失敗後の再試行 | 保存中に消した入力が、失敗した古い変更から再試行対象へ復活する | 消した項目を再試行対象から除外 |
| 戻るの連打 | 保存待ちの間に戻るを複数回押すと複数画面分戻り得る | 1回の離脱だけ実行 |
| ゴミ登録 | Reactの再描画前の連打で同じ登録処理が複数回走る | 同期的な実行中フラグで防止。失敗後は入力を保持して再試行可 |
| ゴミ管理 | 登録・削除・非表示・再表示が重なり得る | 管理画面の変更処理を共通の実行中フラグで保護 |
| 初期設定 | 完了ボタンとスキップボタンの連打で初期設定の確定が重なる | 初期設定の確定を1件に制限 |
| 設定画面 | 全体設定・色設定・Google認証・同期・天気選択・通知変更が再描画前に重なる | 同じ種類の処理の二重起動を防止し、成功・失敗とも解除 |
| 通知設定 | 許可拒否やエラーが「生活リズム」の中に表示され、通知欄から見えない | 通知欄に専用メッセージを表示 |
| 家電解析 | 画面から戻った後もクライアントの問い合わせが続き、遅い結果をローカル保存し得る | 離脱時に通信を中断し、中断後の結果を保存前に破棄 |

家電解析の中断はクライアントの問い合わせ・結果反映を止める。既にサーバーで受理された解析ジョブを取り消す仕様は追加していない。

## iOSで確認した内容

検証専用のiPhone SE相当（375×667、iOS 27）を画面操作した。既存の開発ビルドに今回のJSを反映し、再インストールやデータ初期化は行っていない。大きいiPhoneの設定画面でも階層を目視確認した。

1. 個別設定でフローリングの周期を17日→21日へ入力。保存ボタンを押さず、SQLiteが21日になったことを確認。
2. 家事をオフにして戻り、もう一度開く。21日とオフが残っていることを確認。
3. 周期0日を入力してもSQLiteは21日のままであることを確認。
4. 検証後、周期17日・有効へ操作で戻した。期間幅2日、負荷「普通」、休日優先オフは維持。
5. クレジットが閉じた状態から開閉でき、保存先の文章が常に下にあることを確認。
6. ゴミ入力例「可燃ゴミ」、毎週／隔週／毎月の選択を確認。
7. ホーム、カレンダー、家事の分類・手順、家電の長文説明、ヘルプの見出しと展開後の本文で文字の段階を確認。小さい画面のカレンダーではゴミカードと家事カードまで見えることを確認。

SQLiteの検証前バックアップと比較し、家電1台の解析・説明データと完了履歴5件が変わっていないことも確認した。元のローカルcheckoutは編集せず、利用中の大きいシミュレーターの家事設定・履歴も操作していない。

## ビルドと検証範囲

- `npx expo export --platform ios --platform android`：両方のHermes bundle生成成功。Webは対象に含まない。
- 通信エラー・Google認証・権限拒否は境界をモックして再現した。今回、実際のGoogleアカウントで再認証・API同期をやり直したものではない。
- Androidはbundle生成と共通処理テストまで。今回の画面操作はiOS。
- 正常な背景移行の保存はテストしたが、OSによる強制終了の直前450msの未確定入力や、全てのOS障害までは保証していない。
- 新しい依存パッケージとDBスキーマ変更はない。既存の家事説明、家電解析データ、完了履歴は移行・削除していない。
