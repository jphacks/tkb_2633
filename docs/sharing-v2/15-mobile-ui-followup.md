# モバイルUI要件の再点検と追加修正

2026-10-29、基点`f232ecc`、`codex/encrypted-group-sharing`。[Phase 6](13-phase6-native-group-completion.md)の開発検査の完了と[前回のUI修正](14-mobile-ui-review.md)を照合し、今回繰り返し指定された要件を再点検した。既存の実装を作り直すのではなく、表示・復旧に残っていた差分を修正した。

## 今回見つけた差分

1. 通常カレンダーの「今日」は、実施期間を超えた家事を別の末尾セクションへ分離していた。そのため、期限間近の普通の家事が、軽い未完了家事や完了家事より下に出た。今日はホームと同じ3日の猶予範囲を含む1つの一覧にし、指定の9段階で並べる。完了直後もカードを消さず、未完了の下へ移す。他の日の表示では、選択日の予定と今日の期限超過の案内を区別する。
2. 通常カレンダーの点・棒は、カードのチェックと違って保存・再読込が終わるまで変わらなかった。同じ家事回の表示用状態を件数にも適用する。家事数の重複除去、前倒し実施時の元の推奨日、旧形式の履歴、再計算で元の予定行がなくなった取消も保持する。通常の未完了判定を別実装へ複製せず、既存のカレンダー判定を共有する。同じ家事回に複数の完了記録がある場合は、1件の取消で他の記録まで未完了と予測しない。別の家事回の完了とは混同しない。この追加境界は自動検査で確認する。
3. 保存成功後に再読込だけが失敗した場合、別の家事を操作すると「保存済み」の案内が消え、古い表示用状態が残る経路があった。読込が成功するまで追加の完了操作を止め、保存済みのチェックと警告を保持する。ホーム・カレンダー双方に読込だけを再試行するボタンを用意し、100回押しても1回の読込へまとめる。同時に始まった別の書込が後で失敗しても、保存済みの警告を隠さない。
4. ホームのリンク・共有領域の切替・保存した家電へのリンクには文字の`›`が残っていた。これもBack・開閉・月移動と同じ共通Chevronへ揃え、文字の色や階層を保持する。読み上げ・検査用のラベルに記号を混ぜない。

実施期間の展開表示は、選択日を実際に含む期間だけを描く。猶予中のカードを今日へまとめても、過去の期間を「今日を含む期間」と表示したり、負の幅の棒を作らない。

本番の39ルートと共通部品を棚卸しし、通常入力が共通部品を使うこと、専用数値欄、共通の文字サイズ、矢印を照合した。この棚卸しは、全39ルートを全データ量・全文字倍率で物理端末から操作したという意味ではない。既存の画面・権限・保存・ルート配線の回帰も実行する。

## 実機と検査方法

Sony I4293（Android 10、ADB）では、既存の合成v1領域`LiFlow-QA-20261027`を初期化せず使用した。通常カレンダーに5件を同時表示し、期限超過のトイレが先頭→完了すると4件の未完了の下→取消で元の5件の順序へ戻ること、各操作が保存後に再び操作可能になることを照合した。録画と新しい画面取得も保持した。端末は残量が少ないため、差分の検査後に消灯した。

iPhone 12（iOS 26.7.2、XCTest）では、月移動、製品名入力と固定Back、連結した説明・設定の分類移動、入力キーボードと解除、固定Back、ヘルプ、収集日、クレジットを再確認した。成功した個別メソッドは`testPostPhase6CalendarApplianceNavigation`（27.868秒）と`testPostPhase6ReadOnlyBooksAndNavigation`（67.264秒）。同じbundleの失敗したメソッドは成功へ計上しない。 最新コード上の`testPostPhase6PriorityCalendarFollowup`も24.917秒で成功し、先頭の期限超過家事の完了→末尾→取消→元の順序→ホーム5件・0件完了を照合した。

途中の失敗も区別して記録する。Androidの開発中更新では、新しく追加したexportを呼べない状態があり、Metro cacheを作り直して実プロセスを起動し直した後、同じ完了・取消を再実行した。配信bundle内の関数定義とexportも確認した。UIAutomatorが画面取得に失敗しても前のXMLが端末に残るため、毎回QA用の旧XMLを消し、新規の取得に成功した場合だけ読むよう検査側を修正した。

iPhoneの最初の説明タップの検査では、共有更新中にタップ後もホームが残ったため、不成功として記録した。その後は端末操作を直列化した。カレンダーの検査では、タブ上からスワイプしていたため本文をスクロールできなかった。開始点を実際のScrollViewの範囲内へ直した。既に保存した検査分の取消を含めて再確認し、元の未完了状態へ戻す。これらの検査手順の変更を、製品側の修正と混同しない。
