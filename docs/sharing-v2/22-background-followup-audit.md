# 背景同期を待つ間の追加動作検査

## 修正した問題

### 失敗が成功として返る

個人Google Tasksの同期は、例外だけでなく`retry`・`authRequired`・`error`という戻り値でも失敗を通知する。workerは例外だけを見ていたため、その3種類を成功として記録し、OSへも成功を返していた。

共有の定期同期でも、家事データ、通知、Google Tasksの例外を内部で捨て、Tasksの失敗を示す戻り値も調べていなかった。これらは他のグループや独立した処理を続けるために捕捉するが、試行が終わった後でworkerへ失敗を伝える。Tasksが無効、または通常の間隔制限によって処理不要の場合の成功・skipは維持する。

再ログインが必要な失敗まで「次回再試行」で直るように見せないため、実行記録の失敗表示は「一部を完了できませんでした」に変更した。各接続の詳細状態は既存のGoogle連携画面に保持する。

修正前に9条件で失敗を成功扱いすることを再現し、修正後は失敗を伝えながら残りの独立した処理も実行することを検査した。

### 最初のグループだけで時間を使い切る

グループの列挙順が固定されていたため、最初のグループでOS workerの時間枠を使い切ると、次回も同じグループから始まり、後ろのグループが繰り返し処理されない場合があった。

通信を始める前に、最後に試したグループのIDだけをアカウント別の端末の安全なストレージへ記録する。次回はその続きから処理し、アプリのプロセスが作り直された後も巡回を続ける。退出・除名されたグループや別アカウントのグループは処理対象に含めない。この位置情報の読取・保存失敗で、本来の同期を中止しない。

修正前に、最初のグループだけで時間枠が終わる条件を再現した。修正後は、別プロセス相当の新しい呼び出し元でも2番目のグループを試し、次に先頭へ戻ることを確認した。
