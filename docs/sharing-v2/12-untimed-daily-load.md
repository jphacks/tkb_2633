# 時刻未設定の家事：日単位の負荷確認

2026-10-29、基点`ce8ada5`。D10の追加指定を優先し、時刻のない個人家事を時間帯の競合・移動へ渡さない。開始時刻を補ったり、時刻や移動候補の確認を要求したりしない。既存の通常Scheduler・天気による日単位の計画は維持する。

## 実装した動作

- 本人の今日の未完了家事の負荷を、本人が設定した重い家事・普通の家事の上限と照合する。上限**以上**で画面に案内を表示する。軽い家事には新しい上限を作らない。
- 共有家事は本人担当と未担当の共通家事だけを対象にし、完了済み・無効・別の担当者の家事を除く。既存通知の同じ対象者判定を共用する。
- 個人家事は既存のホームの選択結果から集計する。今日まで表示される期限超過の未完了カードも数え、完了したカードは除く。元の個人DB、予定日、履歴、Google対応表、共有Outboxを変更しない。
- 個人と共有の地域・今日が同じ場合だけ合算する。異なる地域は元の日付・地域を明記した別集計にする。個人データが未確認の場合、確認できた共有分だけを表示し、個人を「空き」と扱わない。
- 端末の共有通知がONでOS通知も許可されているとき、既存の単一ワーカーから負荷を確認する。同じ本人・グループ・日付の通知は1回まで。画面上の案内はその後も最新の集計で更新する。
- 送信前に負荷と通知設定を読み直し、本人・グループ・参加状態、日付、処理時間枠を確認する。SQLiteへ保存する通知済み印は私的な値で、共有イベント・完了履歴にはしない。
- OS要求の応答を失った場合は通知済み印を保持し、再送による重複を避ける。OS任せの背景実行や確実な配達を保証するものではない。

即時通知のOS処理は完了通知と共用し、同じアプリ内の通知キュー・予約上限を守る。負荷通知の失敗だけで既存の受信時完了通知を省略しない。退出時は該当する本人・グループの通知だけを片付け、個人・v1・別グループ・検査用通知を保護する。

## 実機検査と検査経路の修正

iPhone 12（iOS 26.7.2）とSony I4293（Android 10）で次を確認した。ユーザーのデータを初期化せず、独立した合成データ・専用のGoogleリストを使った。

- 実Googleアカウントで合成3件を接続。アプリとGoogleの両方向の完了・取消、同じ家事回とGoogle IDの期日変更、プロセス再起動後の対応保持、検査用3件だけの削除。
- 合成の個人設定2件について、確認中と追加後それぞれの再起動復元、元設定・履歴の保持、二重追加の防止。
- 合成の完了通知1件について、OSへの要求、実表示と内容、他領域を残した片付け。

再表示直後のTasks検査が未準備の内部同期portを読む不具合を修正した。共通の純粋な予定投影と保存済みの対応表を使い、余分なGoogle読取を増やさない。通知検査はNative辞書のキー順序だけで失敗していたため、全JSON値を保ち順序を正規化した。通知の内容変更や削除は引き続き検出する。これらは検査経路で再現した不具合であり、通常画面の同期が失敗したという意味ではない。

XCTest用の一時的なRootリンクは削除し、元のソースとの一致を検証した。共用するOS表示経路は両実機で通ったが、新しい負荷種別そのものの独立したOS実配達、自然なバックグラウンド実行の保証、通常v2グループの異種OS総合を成功とは数えない。[hash付きの実行記録](evidence/2026-10-29-untimed-load-and-native-checks.json)に範囲を明記する。

D11の回答により、既存v1を保持したまま新規v2を先行し、既存グループの変換画面・全端末切替は今回のPhase 6完了条件から外した。準備済みの移行コアと回帰検査は保持する。Phase 6全体やその後の全ページUI調整を完了扱いにはしていない。
